Sample SPDX 2.3 SBOM from image-builder build --with-sbom

image-builder can write an SPDX 2.3 SBOM next to a disk image it builds. The SBOM describes the image file and the RPMs installed in it. This page shows one real SBOM, field by field, with where each value comes from, the Red Hat guidance it should meet, and the questions we need ProdSec to answer.

Scope (MVP)Package-based disk images only (qcow2, raw, ISO, …). Refused for bootc and ostree images, for --with-extra, and for builds with more than one output artifact.
ContentsThe image file plus every RPM in the image's payload depsolve (buildroot RPMs excluded), each once, sorted by NEVRA.

    Build typeReal build. The image was built by osbuild and the SBOM's image checksum is the SHA-256 of that qcow2 file. Nothing on this page is a stand-in.

    SBOM filecentos-9-qcow2-x86_64.spdx.json, 528,269 bytes, sha256 df2ebe174a0f39fd07cae9ae2fed5544966260cdc14dabc84b31d01d48702e16. Unmodified output.
    Why CentOS StreamRHEL repositories need a subscription on the build host. For a RHEL image the code maps vendor “Red Hat, Inc.” to pkg:rpm/redhat/… and adds supplier: Organization: Red Hat to those RPMs; everything else is the same.
    Code path manifestgen payloadPackages → build finishes → writeImageSBOM (hash image, then sbom.Generate) → protobom v0.6.2 SPDX 2.3 writer. task build-image --with-sbom uses the same writer with the package list saved by task init.

    Validation (run 2026-11-16)

    JSON parsepass
    SPDX 2.3 JSON schemapass, 0 errors: official schema at spdx-spec v2.3, and ProdSec's copy sbom/spdx-2.3-schema.json in security-data-guidelines (python-jsonschema, Draft 7).
    spdx-toolsvalid: pyspdxtools -i (spdx-tools 0.8.5), exit 0.
    SBOM-Gradergrade D with sbomgrader 0.2.5, the tool ProdSec's Compliance Validation section names. It has no disk-image profile, so we used --content-type generic (build and release cookbooks; same result). All MUST rules pass. SHOULD failures: versionInfo, externalRef (purl) and supplier on packages[0], the root image (Q1, Q3). The grader reports only the first failing element; the 474 CentOS RPMs have no supplier either (Q4). The release cookbook reports “RPM packages have a repository_id qualifier” as passing although no purl has one; we did not investigate why.
